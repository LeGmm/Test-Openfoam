二、审计方法

三条原则：跑，不看文档；换算例，不动既有结果；每个判断配一条可复现的证据。 具体动作：

  1. 用 h5py 直读 FLTG.2-Setup-Output.cas.h5，枚举 cell zone / face zone / shadow 配对， 独立复算每个面区的面积与每个单元的体积（Newell 向量面积 + 散度定理），不依赖项目自带脚本。
  2. 在独立目录做完整双区域转换，再跑 OpenFOAM 官方 checkMesh 两区域——这是唯一有权威性的网格判定。
  3. 复制字典组装 CHT 算例，跑项目自带 preflight --checkmesh 门禁。
  4. 生成 Step 2 单区域算例，跑 align_step2_thermo.py + preflight。
  5. 用 62,158 面界面做 map_interface_T.py verify 压力测试（同时量耗时与内存）。
  6. 复核既有结果：从 caseCHT_qishi/9000 场文件自行算通量加权出口温度， 独立判断 Step 1 是否真的收敛；读 log.step2e 定位 Step 2 崩溃机理。

结构性缺陷

1. cases/ 目录不存在，但四个脚本 + 一份 README 全都依赖它

实测 ls cases → No such file or directory。于是 prepare_all_structures.py（批量转 8 结构）、 compare.py（跨结构排名）、mesh_stats.py（面积统计）、run_all.sh（一键跑）全部失去输入。 "8 结构对比"这条主线目前是断的，只剩 v8_1 一条手工链路。

2. run_all.sh 与两步共轭 SOP 相互矛盾

脚本第 51 行直接跑 multiphaseEulerFoam，完全没有 Step 1。也就是说"一键跑全部结构" 用的是已被否决的"coldWall 直接定 5℃"简化路线——跑出来的会是过度冷却的结果。 另外第 61 行用 alphaPhi.liquid（体积通量，m³/s），而 controlDict 的指标用 alphaRhoPhi.liquid（质量通量，kg/s）：同一指标在同一项目里有两套量纲。

纠正：Step 2 的阻塞不是"薄片单元"

项目文档（README 第七节、工作记忆）把 Step 2 的崩溃归因为"双大面平行薄片单元"。我用统一口径 （形状因子 q = V / Amax1.5，等价于厚度/边长）量了两套网格：

  • v8_1：V<1e-11 的 7,624 个单元，q 中位 0.43，最小 0.152（长宽比约 7），q<1e-2 的一个都没有；
  • v8_8 流体区：全部单元 q 中位 0.50，q<1e-3 的 0 个；
  • 官方 checkMesh 独立复核：最大长宽比 9.23 / 8.54。

三条证据指向同一结论：两套网格都不存在薄片单元。那些小体积单元只是"小"，形状是正常的 （等效 67–96 µm 的等轴小胞）。真正的约束是小体积单元设定了时间步上限，叠加相变源项刚性。 这意味着"给进出口面下层加密"这张处方没有对准病根——加密只会制造更多更小的单元。

Step 2 崩溃的实际形态（case_qishi / v8_1）

deltaT = 2e-06（固定） → t=2e-06 时 Co max 0.0055 → t=4e-06 时 Co max 141.6 ← 一步之内速度爆炸 → 随后 FOAM_SIGFPE 终止，只写出 4e-06

Co 在固定小步长下跨 4 个量级，这不是 CFL 超限（若是，调时间步即可），而是 压力—速度耦合在极小体积单元处失稳后的雪崩。这一步没有定位到具体单元，我不下断言； 但可以确定的是：把它当成"网格有薄片"来处理，方向错了。

九、缺口清单与建议

P0 —— 不给结论就不能算完

  1. Step 2 必须先在一个结构上跑出可用的稳态。在此之前，"8 结构冷凝效率对比"没有任何数据支撑。 建议先在 v8_1 上把 deltaT 与相变源项松弛做成参数扫描（而不是改网格）， 并用 ablate.py 记录崩溃前场统计——项目已经有这个工具，只是要真的用它定位单元级别的原因。
  2. 重新校准 Step 2 的根因判断。已验证不是薄片。下一步应直接输出崩溃时刻的 Co、|U|、V、Ap=V/dt 四张场，找"高 Co ∧ 小 V"的交集单元， 再判断是压力方程病态还是相变源项刚性。
  3. Step 1 拉长到能量比 <1.05 再取 T_int。v8_1 已到 1.080，方向是对的，只差迭代； 但请注意 v8_8 的代价是 5.2 倍。

P1 —— 用 v8_8 之前必须补

  1. 补一个 generate_case_cht.py：现在 CHT 字典靠人从 caseCHT_qishi 拷贝， 换结构要手工改补丁名——这正是最容易出错的地方（wall vs outer vs interface）。
  2. 把 A_IN 改成从 polyMesh 现算，并在 preflight 里加一条 "入口面积 vs 配置值"的校验，偏差 >1% 就 FAIL。
  3. 在 preflight 里加一条：coldWall 若仍是 uniform（未映射）则 WARN， 避免"忘了 map 就开跑"。
  4. 修 README §三 的顺序：转换 → 先补 system/controlDict → 再 checkMesh。
  5. 修 run_all.sh：删掉或重写成两步流程，并把指标统一到 alphaRhoPhi.liquid。

P2 —— 论文层面的假设必须写清

  1. 无浮升力：Step 1 用 rhoConst，Gr/Re² ≈ 1.2 属混合对流区，这个近似要披露， 建议至少做一组 heRhoThermo + perfectGas 的对照看 T_int 差多少。
  2. 单向耦合：凝液潜热未反馈给固体，冷板热流偏低。
  3. 相变机理不同：Fluent 是 Lee 温度驱动，OpenFOAM 是界面饱和 + 组分扩散。 绝对值不可直接对比，只能比结构排序——这一点 README 已写对，应保留。
  4. Eulerian 分散相对壁面膜状冷凝是近似；若要液膜形态须转 VOF。

十、最终判定

问题答复
这个项目整体可靠吗？ 骨架可靠，结论不可用。转换、门禁、映射三段工程实现扎实且可复现； 但主结果（冷凝效率）一条都没有，Step 1 也还差一点收敛。属于"工具已经做好、实验还没做完"的状态。
