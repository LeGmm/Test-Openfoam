二、根因：源码级的铁证

OF8 的 multiphaseEulerFoam 在每个压力修正步无条件执行（pU/pEqn.H:391）：

p = max(p_rgh + rho*gh, pMin); // ← 每步都算，p 被 p_rgh 完全决定 p_rgh = p - rho*gh; forAll(phases, phasei) { ... rho() += psi()*(p_rgh - p_rgh_0); } // 密度按 p 更新

也就是说：p_rgh 在这个求解器里就是绝对压力，0/p 里写的 101325 第一步就被覆盖。 气相是 perfectGas，密度由 p 算出。官方教程 laminar/bubbleColumnEvaporating/0/p_rgh 也正是 uniform 1e5 + 出口 prghPressure p=1e5。

而项目的生成器写的是 p = 101325 / p_rgh = 0（表压口径）。于是：

p_rgh ≈ 0.045 Pa → p = max(0.045 + ρgh, pMin=10000) = 10000 Pa ρ = p/(RT) = 10000/(287×297) = 0.117 kg/m³ （应为 1.145，差 9.8 倍） 出口 p_rgh 固定 0，内部 ~1e4 → 一个步长内速度 = 3120 m/s → FOAM_SIGFPE

现象与根因逐条对上

实测现象用「压力口径错」如何解释
崩在第一个时间步内（t=2e-6 时 Co 已 143）初始场不自洽，不是稳定性极限，所以调 dt 没用
爆点全在 y≈+30 mm 出口/入口平面下 0.2 mm 的一层那里正对固定压力边界，压力落差集中在这一层
T.gas 出现 −0.70 K 与 1037 K（1,904 个单元）速度 3120 m/s 使动能 ½U²≈5e6 J/kg 压过内能，焓方程反解出负温
1,904 个异常单元 100% 落在 y∈[29.71, 29.91] mm局部事件，不是全场失稳
关掉相变照样崩因为与相变无关
ΣY(air+H2O) = 1.0000 处处成立不是组分失衡

为什么之前一直没找到

因为 case_qishi/0 是热启动过的：0/p_rgh 不是 uniform 0，而是 64,729 个 ≈0.045 Pa 的值（从 Step1 的零参考场直接拷过来的）。这个数字看起来"像那么回事"， 又小到不会让人警觉，于是被当成动压而不追问它的参考基准。而 0/p 是 101325——两者相差整整一个大气压。

五、"正确跑出来"还差三件事（都不是数值问题）

① 物理时间远远不够

V_fluid = 51.9 cm³ Q = 17.47 cm³/s τ = V/Q = 2.97 s

现在只跑了 20 ms = 0.7% 个停留时间。要让出口指标代表"这个结构的冷凝能力"， 至少要 1 个 τ（≈3 s），最好 2 个 τ 看是否走平。这决定了工时，见第六节。

② 出口凝液流率这个指标会读成 0

mdot_cond 从 1.54e-08 一路衰减到 −3.9e-11（约等于 0）。原因不是没冷凝， 而是凝液在冷壁上积着、排不到出口：coldWall 的 alpha.liquid 是 zeroGradient、 U 是 noSlip，没有壁面液膜/排液模型，凝液贴着壁面不动。

现在的冷凝量其实可以从气相侧闭合出来：入口水蒸气 5.783e-07 kg/s，出口约 3.94e-07 kg/s， 差 1.8e-07 kg/s（32%）——但先别急着用这个数，见下一条。

③ 初始组分场是被"人工饱和"过的

warmstart_step2.py 的 --no-yinit 默认逻辑是 Y0 = min(Y_inlet, Y_sat(T))，所以 0/H2O.gas 的范围是 0.0055~0.0289（中位 0.0191）， 冷的单元一开始就已经"凝到饱和"。这意味着前一个 τ 内的冷凝量不是物理结果，是初场残留。 必须先跑到 1τ 以上再看数，并且论文里要说明这一步。

顺带一个量级校核

种子液相 α_l=1e-6 全域 → 液相总质量 51.8 µg；20 ms 内实际凝结约 3.7 µg（7%）。 所以早期 α_l 场里 93% 是种子，不能拿 α_l 云图当"凝液分布"用——至少要跑到 0.3 s （种子等效时间）之后，或者把种子降到 1e-8 并重验稳定性。
